# Field guide: Before relying on a generated output

Use this page when you need a check, not a whole evaluation program. Start without asking the generator to grade its own reply.

1. **Separate the statements.** For each claim, record subject, unit, time window and scope. Put recommendations in different rows from observations.
2. **Find one thing that could disagree.** A primary record, independently made calculation, controlling policy, or known test case beats a second paraphrase.
3. **Make the comparison explicit.** State the operands and denominator. Record stale, unavailable and missing results. A correctly formatted response can fail all three steps.
4. **Choose a verdict with a limit.** Use supported by this evidence, contradicted by this evidence, or not established. Name the further evidence or reviewer that would change your conclusion.
5. **Treat consequences separately.** A valid number does not approve an action. For a proposed change, check authority, independent state and safety of retry.

| Claim and scope | Evidence locator | Check or calculation | Decision and unresolved item |
| --- | --- | --- | --- |
| Reported count, named branch and window | Original table cell and revision | Transcribe, then independently compute any comparison | Use only for the scope tested |
| Causal claim from a before/after table | A comparison that can address what would have happened otherwise | State and assess its assumptions | Withhold if those assumptions or the comparison are missing |
| Tool allegedly completed a consequential action | Authorized action, trusted trace, fresh state | Reconcile all three before retrying | Stop or escalate if authority or outcome is unknown |

If time is short, narrow what you rely on rather than certifying the whole output. The [full first worked chapter](../chapters/01-make-the-claim-testable.md) explains the machinery; the [workflow chapter](../chapters/05-audit-the-workflow.md) handles a claim with actual consequences.
